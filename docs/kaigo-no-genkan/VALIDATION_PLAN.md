# 検証計画: 介護のげんかん

**Version:** 0.2  
**目的:** 作る前に、「動くか」「戻るか」「渡せるか」を潰す。  
**形態:** コード少なめ（フォーム + スプレッドシート + 手動or半自動の結果返却）  
**対象の絞り:** v0.2 のウェッジに合わせ、**退院前後のケースを過半数**にする。

---

## 1. 検証する仮説（優先順）

| ID | 仮説 | 失敗したら |
|---|---|---|
| **H1** | 3問（L1）で返す暫定の一手でも「役に立つ」と感じる | 段階設計をやめ、一括問診に戻す／課題の再定義 |
| **H2** | 次の一手を見た家族は 48h 以内に最初の連絡をする | 台本・緊急性・届け方を見直し。課題自体の再定義 |
| **H3** | 引き継ぎシートを専門職との面談で実際に提示する | シートを家族内共有に用途変更／付随物に格下げ |
| **H4** | 節目（更新・退院）の通知で再訪する | リテンション前提の事業計画を捨て、一回性ツールとして再設計 |
| **H5** | 「ChatGPTでいい」と言われない差を体感できる | 状態・土地・成果物のどれが効いているか特定して集中 |
| H6 | サイト内に相談先が出ると安心感が上がる | 探し方導線でも許容されるか再測定 |
| H7 | 病院の退院支援部門が配布に前向き | 企業B2Bを先行チャネルに戻す |

**最初に潰すのは H1 → H2 → H3。** H4 は時間がかかるため、簡易版を並行で観測する。

---

## 2. 実験設計

### Experiment A — 段階問診MVP（コア）

**対象**
- 親の退院が決まっている、または介護がこれから始まる子世代
- **退院ケースを半数以上**、遠距離を3割以上
- 目標サンプル: **30–50人**（質的インタビューはうち 8–10人）

**募集**
- 知人・SNS・介護系コミュニティ
- 可能なら病院の退院支援部門 or 企業1社のパイロット

**手順**
1. L1（3問）に回答 → **即座に**暫定の一手1件を表示（ここは自動化する価値がある）
2. L2 に進んだ人へ、24時間以内に一手3件＋台本を返却
3. 希望者に **引き継ぎシート**（手作りで可）を返し、面談で使ってもらう
4. 48時間後にフォローアンケート
5. 2〜4週間後に再訪観測（H4簡易版）

**計測**

| 指標 | 成功の目安 |
|---|---|
| L1 到達→「役に立った」 | ≥ 60% |
| L1→L2 進行率 | ≥ 55% |
| 48h以内に連絡実行（自己申告） | ≥ 40% |
| シートを面談で提示した | ≥ 20% |
| 30日以内の再訪・返信 | ≥ 25% |

**インタビューで聞くこと**
- 3問だけの回答は物足りなかったか、ちょうどよかったか
- どの一手が実際に効いたか
- シートを専門職に見せたか。見せなかったなら理由
- 同じことを ChatGPT に聞いたか。聞いたなら何が違ったか
- 次に戻ってきたくなるのはどんな時か

---

### Experiment B — LLM比較（H5）

同じ状況を、参加者に **(a) 汎用LLM** と **(b) げんかん** の両方で試してもらう。

聞くこと:
- どちらが行動につながったか
- 連絡先の正確さへの不安に差はあったか
- 「渡せるもの」の有無をどう感じたか

**判断:** 差が出ないなら、UIではなく**状態・土地・成果物のどこに投資すべきか**を決め直す。

---

### Experiment C — 専門職ヒアリング（H3・H7）

病院MSW・退院支援 3–5人、ケアマネ／包括 3–5人に30分。

聞くこと:
- 家族の準備不足で何分失っているか
- 引き継ぎシートに何が書いてあれば嬉しいか（逆に不要な項目は）
- 家族に配布する導線はありうるか（QR・案内紙・口頭）
- 中立性・広告についての懸念

成功の兆し: 「この形式なら受け取りたい」が過半数、配布に前向きが1施設以上。

---

### Experiment D — 企業ヒアリング（並行・少数）

人事・総務 3–5社に30分。

- 介護周知・相談窓口の現状
- 「周知した数」ではなく「初動に到達した数」を出せることの価値
- LCAT等との併存余地、予算感、決裁者と必須条件

## 3. Go / No-Go（v1開発に進む条件）

**Go**
- H1 と H2 が目安をクリア（または明確な改善レバーが見える）
- H3 か H4 のどちらかに手応え（成果物 or リテンションのいずれかが立つ）
- 「診断してほしい」誤解がコピーで制御可能
- 包括データ運用の覚悟 or 先行エリア限定で開始できる

**Pivot 候補**
| 症状 | 寄せ先 |
|---|---|
| 完了するが誰も連絡しない | 有人併走型（コンシェルジュ） |
| シートだけ評価が高い | 引き継ぎシート単体プロダクト |
| 再訪が皆無 | 一回性ツールとして病院・企業へ配布特化 |
| ChatGPTと差が出ない | 土地データ（連絡先の正確さ）に全振り |
| 「包括に聞けばいい」で満足 | 企業の義務対応ツールへ |
