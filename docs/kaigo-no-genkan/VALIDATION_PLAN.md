# 検証計画: 介護のげんかん

**目的:** 作る前に、「答えるか」「動くか」「役に立つか」を潰す。  
**期間目安:** 2〜3週間の学習サイクル（カレンダー日数ではなく、実験の深さで見る）  
**形態:** コード少なめ（Typeform + Notion/スプレッドシート + 手動or半自動の結果返却）

---

## 1. 検証する仮説（優先順）

| ID | 仮説 | 失敗したら |
|---|---|---|
| H1 | 初動家族は 12–18 問の問診を完了する | 質問削減／分岐見直し |
| H2 | 結果の「次の3手」で 48h 以内に最初の連絡をする | 台本・緊急性・届けるタイミングを見直し。課題自体の再定義 |
| H3 | サービス種別レコメンドは「面談前に欲しい」と感じる | 種別UIを結果の下位に下げる／後回し |
| H4 | サイト内に相談先が出ると安心感が上がる（検索不要） | 探し方導線でも許容されるか再測定 |
| H5 | （事業）企業は「実行ツール」として費用対効果を感じる | B2C／専門職配布へ寄せる |

**最初に潰すのは H1 → H2。**

---

## 2. 実験設計

### Experiment A — 問診MVP（コア）

**対象**
- 親の介護が「これから／始まったばかり」の子世代
- できれば遠距離 or 共働きを半分以上
- 目標サンプル: **30–50人**（質的インタビューはうち 8–10人）

**募集**
- 知人・SNS・介護系コミュニティ
- 可能なら企業1社の希望者パイロット（任意）

**手順**
1. Typeform 等で問診（状況＋ニーズ）
2. 回答を受け、24時間以内に結果を返却  
   - ステージ  
   - 次の一手 1–3（台本つき）  
   - サービス種別 3–5  
   - （可能な範囲で）包括の連絡先 ※手調べでも可
3. 48時間後にフォローアンケート
4. 希望者に15分インタビュー

**計測**

| 指標 | 成功の目安 |
|---|---|---|
| 問診開始→完了 | ≥ 60% |
| 「結果が分かりやすい」（4–5 / 5） | ≥ 70% |
| 48h以内に連絡実行（自己申告） | ≥ 40% |
| 「家族に共有したい」 | ≥ 50% |
| NPS or「また使いたい」 | 過半数 |

**インタビューで聞くこと**
- 結果の前に止まっていた理由
- どの一手が実際に効いたか
- 怖かった／足りなかった情報
- サービス種別は不要だったか、もっと欲しかったか
- 番号がサイト内にあることの価値

---

### Experiment B — サービスレコメンド単体（Aに埋め込み可）

結果メール／ページで種別レコメンドのブロックを出し、  
「この情報はどれくらい役立ちましたか？」を単独採点。

- 役立つ ≥ 4/5 が過半数なら v1 に残す  
- 低ければ「相談メモの付録」に格下げ

---

### Experiment C — 企業ヒアリング（並行・少数）

人事・総務 3–5社に30分。

聞くこと:
- 介護周知・相談窓口の現状
- LCAT等との併存余地
- 「従業員が次の一手まで進むツール」への予算感
- 導入の決裁者と必須条件（セキュリティ、匿名レポート等）

成功の兆し: 「パイロットしたい」が1社以上。

## 3. 学習バックログ（実験後に更新）

| 学び | プロダクトへの反映 |
|---|---|
| （例）質問が長い | 必須10問に削減 |
| （例）退院ケースだけ動く | 入口CTAを退院・物忘れに寄せる |
| （例）番号の正確性が不安 | 鮮度表示＋報告を必須化 |

---

## 4. Go / No-Go（v1開発に進む条件）

**Go（すべて推奨）**
- H1 と H2 が目安をクリア（または明確な改善レバーが見える）
- 「診断してほしい」誤解が面接で多発しない（コピーで制御可能）
- データ運用（包括）をやる覚悟 or 先行エリア限定で開始できる

**No-Go / Pivot**
- 完了はするが誰も連絡しない → コンシェルジュ併走型へ
- そもそも「包括に聞けばいい」で満足 → 課題が弱い。企業の義務対応ツールに寄せる等
