# PRD: 介護のげんかん

**Version:** 0.1  
**Status:** Draft  
**Platform:** モバイルWeb（PWA可）  
**One-liner:** 介護版Ubie。家族の状況を聞いて、次にやることと合いそうなサービス種別までサイト内で案内する入口。

---

## 1. Problem

初めて在宅介護に直面した家族は、情報は多くても「自分は今なにをすればいいか」が分からず止まる。

- 介護保険は申請主義で、動かないと何も始まらない
- 窓口が包括・市役所・病院MSW・ケアマネに分散している
- 記事や自治体HPは静的で、自分のケースに落ちない
- 更新・住宅改修の事前申請など、期限付き手続きを落としやすい

**空白:** 問診 → 次行動 → サービス種別、まで一気通貫の大衆向け入口。

---

## 2. Goals / Non-goals

### Goals
- 初動家族が 48 時間以内に「最初の連絡」（包括／窓口／MSW）まで進める
- ケアマネ／包括面談前に、困りごとを言語化したメモを持てる
- 合いそうな介護サービス種別を理解し、相談の土台ができる
- 連絡先探しを Google に逃がさず、サイト内で完結させる

### Non-goals（v1）
- 要介護度の推定・診断
- ケアプランの自動作成
- 単一事業所の押し売りレコメンド
- 日常介護記録の代替
- ネイティブアプリ必須

---

## 3. Users

| 優先 | セグメント | ニーズ |
|---|---|---|
| P0 | 40–60代の子世代ケアギバー | 今やることを短時間で知りたい |
| P1 | 遠距離・共働き家族 | 台本・共有・電話で進めたい |
| P2 | ケアマネ／包括 | 準備できた家族と面談したい |
| P3 | 企業人事 | 介護離職防止・周知義務の実ツール |

---

## 4. Product Principles

1. **診断ではなく案内**（要介護度を当てない）
2. **次の一手は最大 3 件**
3. **ケアマネの前工程**であり代替ではない
4. **サイト内完結**（検索エンジンへ逃がさない）
5. **サービスはまず種別**、事業所はデータ後続

---

## 5. User Journey (v1)

1. LP → 問診開始
2. 状況問診（12–18問）
3. ニーズ聴取（生活上の困りごと）
4. 結果画面
   - ステージ
   - 次の一手 1–3（手順・台本・完了条件）
   - サービス種別レコメンド（理由つき）
   - 市区町村に応じた包括等の連絡先（自DB）
   - 困りごとメモ／家族共有
5. `tel:` で発信 → 「連絡した」チェック → 次アクション解放

ユーザーがサイト外で行うのは **電話／窓口訪問** と、任意の家族共有リンク閲覧のみ。

---

## 6. Functional Requirements

### 6.1 問診
- きっかけ、年齢帯、市区町村、距離、住まい
- 認定有無・（任意）要介護度・有効期限
- ケアマネ有無、包括連絡有無
- 困りごと、緊急度、退院予定、実行体制、今すぐ電話可否

### 6.2 エンジン
- Stage 判定（S0–S6）
- Action 発火（最大3、優先度つき）
- ニーズ → サービス種別マッピング
- Guard: 断定禁止、確認先併記、鮮度表示

### 6.3 結果・完了支援
- 電話台本、手順、完了チェック
- 困りごとメモ、ケアマネ面談アジェンダ
- 家族共有リンク（閲覧＋進捗）

### 6.4 連絡先・事業所データ
- 厚労省オープンデータ等を定期取込
- v1: 地域包括支援センター＋市の介護窓口を優先
- 表示: 名称・電話・住所・データ時点
- 欠落時: フォールバック案内（断定番号は出さない）

### 6.5 サービスレコメンド
- v1: サービス種別＋理由＋注意（限度額・事前申請・ケアマネ調整）
- v1.1+: 同市区町村の事業所一覧（情報公表データ）
- 単一推し・非開示アフィリエイト禁止

---

## 7. Data Model (概要)

- `Municipality`（コード・名称）
- `Center`（包括等: phone, address, source, sourced_at）
- `ActionTemplate` / ルール
- `ServiceType` / ニーズ対応表
- `Session`（問診回答・結果・共有トークン）

連絡先は手メンテ電話帳にしない。公式ミラー＋鮮度メタデータを必須とする。

---

## 8. Success Metrics

| 指標 | 初期目標（目安） |
|---|---|
| 問診完了率 | ≥ 60% |
| 48h 以内の初動実行率 | ≥ 40% |
| 準備メモ DL / 共有率 | ≥ 30% |
| 「また使いたい／家族に共有したい」 | ≥ 50% |

事業KPI（後続）: 企業パイロット契約、専門職配布数。

---

## 9. Monetization (方針)

- 家族向け入口は無料
- 主柱: 企業福利厚生／両立支援
- 副: 居宅・包括向け準備サマリー
- 補助: 審査付き保険外送客（信頼優先）
- 小さめ: 家族プレミアム（共有・期限・専門家チャット）

---

## 10. Risks & Mitigations

| リスク | 対策 |
|---|---|
| 制度・番号の誤り | ルール優先、鮮度表示、確認先必須、報告導線 |
| ケアマネ反発 | 「前工程」「プランは専門職」を明記 |
| 自治体データ欠損 | 包括に絞る、カバレッジ開示、フォールバック |
| B2C収益化困難 | 最初から企業B2B導線 |

---

## 11. Milestones

1. **検証:** 手動結果返却の問診MVP
2. **v1 Web:** 自動エンジン＋結果＋共有
3. **データ:** 包括連絡先のサイト内表示
4. **B2B:** 企業パイロット
5. **拡張:** 事業所一覧、期限リマインド、PWA通知
